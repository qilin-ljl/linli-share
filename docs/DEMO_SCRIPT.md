# NeighLoop｜手机端 5 分钟录制执行稿

> 目标成片 **5:00**，建议手机竖屏录制后剪掉输入和等待的空白。主线是“买家发现需求 → 卖家发布 → 私聊预约交接 → 社区数据变化”。本地演示使用两位已加入 **绿荫花园小区** 的用户：买家 **王思思**，卖家 **林小雨**。部署上线不属于这条视频。

## 一、收尾复查结论

| 项目 | 结论与录制时的处理 |
| --- | --- |
| 手机首页双频道 | 每次重新打开或刷新项目先有约 2.6 秒品牌动效，然后进入市集；顶部可切“闲置市集／邻里需求”。站内切页不重复播放。市集推荐卡能横向滑动，右上角邻里动态滚动页面时保持固定。王思思有已完成领取记录，卡片可出现“根据你曾领过的家居好物”。这来自真实 `transactions`，不是浏览记录。 |
| 发布入口 | 底部“发布”弹出“发布闲置物品／发布我在找”，进入两张不同的发布页面；需求浏览频道没有发布表单。手机闲置发布页的 AI 描述和价格按钮已放进对应步骤，不必滚到整张表单末尾。 |
| 需求讨论 | 需求公开、地图按楼栋汇总；讨论回复可附回复者自己的在架物品。演示数据库已补两条带物品链接的回复，可直接展开查看。 |
| 私聊和预约 | 详情页保留公开“邻里留言”，手机端预约操作集中在“消息”。预约申请、确认、出发、到达与领取码交接按双方会话处理；卖家看不到买家的领取码。AI 回复标注“AI 邻里助手”。 |
| 数据与材料 | 社区数据位于地图下方；完整 ER 图已按现有数据表重画，另有录屏用的核心链路简图。技术栈文档已改成当前的推荐和消息规则。 |
| 仍需注意 | 真机不能访问电脑的 `127.0.0.1`。录制时要按下方局域网方式启动；本地 HTTP 下不要把系统 GPS 定位作为必演步骤。支付担保、评价和纠纷处理未实现，视频不要宣称具备。 |

## 二、录制前检查：真机访问本地项目

电脑和手机连同一个可信 Wi-Fi，先停止仅监听 `127.0.0.1` 的旧开发服务。然后在电脑 PowerShell 查当前无线网卡 IPv4 地址；地址可能随网络变化，录制当天重新确认：

```powershell
Get-NetIPAddress -InterfaceAlias 'WLAN' -AddressFamily IPv4 | Select-Object IPAddress
```

把查询到的地址替换下面的示例。后端在 `backend` 目录启动；已在 `backend/.env` 配置的 DeepSeek Key 由后端读取，**不要在录屏或命令画面展示密钥**。本地双人演示需要 `NEIGHLOOP_DEMO_MODE=true`；前端 `frontend/.env.local` 需要 `VITE_DEMO_MODE=true`。首次准备数据或需要补齐示例讨论时，可先运行一次 `seed.py`，它不会覆盖用户已发布的物品。

```powershell
# 后端终端：位于 backend 目录
$demoIp = '192.168.x.x'
$env:CORS_ORIGINS = "http://${demoIp}:5173,http://127.0.0.1:5173,http://localhost:5173"
# 首次准备演示内容时可运行：.\.venv\Scripts\python.exe seed.py
.\.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
```

```powershell
# 前端终端：位于 frontend 目录
npm run dev -- --host 0.0.0.0
```

手机打开 `http://<电脑无线网卡IP>:5173/`。前端默认以当前网页的主机名请求 8000 端口；若 `frontend/.env.local` 单独设置过指向 `127.0.0.1` 的 `VITE_API_URL`，录制前删去该覆盖并重启前端。若手机只看到页面、没有商品，先在手机浏览器打开 `http://<电脑无线网卡IP>:8000/api/bootstrap` 检查 API 是否可达，再核对 `CORS_ORIGINS` 和 Windows 私有网络防火墙许可。不要把服务端口开放到公网。

### 拍摄准备卡

1. 手机打开勿扰模式、锁定竖屏，建议用系统录屏；截图或剪辑统一按 9:16 竖屏导出。录制前在相册放一张和商品一致的**实物照片**，不要在视频中上传他人的照片。
2. 用浏览器打开项目根地址 `/`，等待约 2.6 秒启动动效后进入双频道首页，再在顶部演示用户切换到 **王思思**。刷新页面也会重播动效；站内切页不会。若已有正式账号登录，先退出；正式账号与 Demo 身份切换不能同时使用。
3. 先在手机上检查：市集能加载、DeepSeek FAQ 能回复、底部“发布”能进入表单。选择绿荫花园小区；本地 HTTP 不把“允许系统定位”作为必演步骤。
4. 发布主线准备商品：建议标题 **“桌面暖光台灯”**；原始描述先写 **“灯光正常，九成新，书桌上用过，外壳没有明显磕碰。”**。根据真实照片改写事实，别让 AI 替你编功能。楼栋选卖家所在 **1号楼**，交接地点选公共区域，至少保留一个**晚于录制时间**的预约时段。默认表单已给出未来时段，录制前仍需核对。
5. 准备一段可复制的需求原话：**“最近想给书桌找一盏不刺眼的小台灯，预算 60 元左右。”**。录制时粘贴比逐字输入稳定。需求必须由用户核对 AI 推测后再发布。
6. [完整 ER 图](ER.png)用于提交；[录屏核心 ER 简图](ER_OVERVIEW.png)和[技术栈简介](TECH_STACK.md)提前存成剪辑素材。它们是材料画面，**不是手机 App 内的页面**。如示例讨论所附物品已经显示“等待确认”，先由该物品发布者确认在架，或换用另一条仍在架的回复。

### 剪辑规则

- 保留每次点击后的**结果画面**。键盘输入、相册选择和等待 AI 的静默时间可以加速或跳切；不要剪到让“发布、预约、成交”看起来发生在点击之前。
- 所有话术用“**已完成领取记录**”“**历史标价参考**”“**AI 助手回复**”。不要说推荐基于浏览历史，也不要把历史标价称为真实成交价。
- 5 分钟内只展示一次完整商品发布与一次完整交接。AI 拍照拆分、批量发布、创建社区、护照等功能可放在补充说明，不挤占这条主线。
- 若 DeepSeek 超时：保留错误反馈 1–2 秒，手动描述继续流程；不要把规则兜底称为实时 AI 生成。若预约时段已过期，改选表单里仍在未来的时段，绝不使用旧种子商品的过期时段。

## 四、录制后核对

- 最终成片在 **4:55–5:05**；没有拍到 `.env`、API Key、真实私人联系方式或系统通知。
- 商品发布后能在市集与地图看到；预约、接受、出发、到达、完成都在**同一物品的双方私聊**里有可见记录。
- 卖家不能直接看到买家领取码；公开邻里留言与私聊在画面里能区分。
- 最后一屏 ER 简图与当前 [完整 ER 图](ER.png)一致；视频里的统计不宣称是虚构“示意数据”。演示社区和种子商品本身是测试数据，应明确标为本地演示。
