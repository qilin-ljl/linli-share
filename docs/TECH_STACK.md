# 技术栈简介

录制视频可使用 [16:9 技术栈卡](TECH_STACK_CARD.png)；本文件是提交用的详细文字说明。

| 层 | 技术 | 作用 |
| --- | --- | --- |
| 前端 | React 19、TypeScript、Vite、React Router、Lucide、Framer Motion | 桌面与手机共用首页双频道、推荐和邻里动态，并提供独立闲置／需求发布、地图、讨论和私人消息 |
| 后端 | Python 3.12、FastAPI、Pydantic | REST API、输入校验、权限与业务规则 |
| 数据 | SQLModel／SQLAlchemy；本地 SQLite、计划上线时用 PostgreSQL | 持久化社区、物品、需求讨论、私聊、预约和成交 |
| LLM | DeepSeek `deepseek-flash`，OpenAI 兼容接口 | 描述润色、需求解析、定价参考、物品 FAQ 与离线回复 |
| 视觉 | 静态 2.5D 社区底图 + React 标记层；本地物品图集 | 不依赖真实地图服务的社区发现体验 |

## 前后端分工

前端负责展示、输入和状态反馈。后端负责社区成员校验、推荐排序、条件筛选、在架确认、预约与交接状态、私聊访问控制、领取码核对、统一 ItemEvent 写入、成交记录、统计聚合和 LLM 请求。所有楼栋数量和看板数字均从数据库计算。

`items.status` 的持久状态为 `AVAILABLE`、`RESERVED`、`COMPLETED`、`ARCHIVED`。超过 72 小时未确认的 `AVAILABLE` 物品在读取时表现为 `UNCONFIRMED`，无需后台定时任务。预约确认后进入 `RESERVED`；卖家核对买家的 4 位领取码时，在同一事务内将预约和物品改为 `COMPLETED`，并写入 `transactions`。

每次重新打开项目先显示约 2.6 秒品牌动效，再进入双频道首页；站内切页不重播。市集的“为你推荐”使用可解释的规则排序：**已完成领取记录的类别**、用户主动选择的类别与交易偏好、同楼栋及发布时间。`item_views` 用于独立浏览统计，不会自动推断用户兴趣。其他在架物品仍会出现，卡片给出推荐原因。

`item_events` 保存发布、关注、预约、出发、到达、取消及完成交接的时间线，完整记录只有发布者能看。社区动态只使用公开事件，手机市集右上角每 8 秒拉取并轮换，页面滚动时保持固定；商品详情每 15 秒刷新交接状态。地图按真实物品状态呈现标记，社区数据位于地图下方。

`private_messages` 按物品和双方用户隔离，预约申请、确认及交接状态也写入对应私聊。消息页提供“我的消息／我想要／我的预约”。发布者的心跳超过 2 分钟未更新时，买家发来的普通问题会得到标注为 AI 的回复；FAQ 快捷问题可主动向 AI 提问。回答只提供物品公开事实和可选时间，未知细节需等发布者确认。

`needs` 为用户主动确认的公开需求；首页的邻里需求频道只负责浏览、筛选与讨论，关键词、类别、楼栋、回应状态和预算筛选由后端处理。发布需求在独立页面，完成后返回频道。`need_replies` 可链接回复者自己的在架物品；同一批需求按楼栋汇总到地图。`need_matches` 只依据确认后的类别、关键词和预算规则生成候选关系。

AI 描述建议只润色用户提供的事实；定价保留三档价格与逐档理由，依据只使用发布者输入、处理目标、同社区历史标价数量和社区自提规则。DeepSeek 失败时，定价明确标记为规则参考，FAQ 使用保守的事实兜底。

## AI Coding 使用

项目由 Codex 协助进行需求取舍、架构与数据库设计、接口和页面实现、种子数据生成、真实 API 接入及测试。人工提供了题目、产品示意图和实施方向，并通过本地演示确认最终体验。

## 提交时说明

这是一个可交互的笔试演示站。邮箱注册／登录使用服务端会话；顶部身份切换只在本地 Demo 模式开放。上线时将数据库和 DeepSeek 密钥分别放在托管数据库与服务端环境变量中，前端只持有公开 API 地址。当前没有支付担保、物流或实时 WebSocket 推送。
